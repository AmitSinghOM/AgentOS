## v0.8.1 — Two inner harnesses, one seam

Patch release on Phase 7. Closes the Phase 7 carry-forward item "PydanticAI inner harness" and lands the refactor a second harness made necessary.

### What ships
- **`agentos-provider-pydantic-ai`** (#48, `providers/pydantic-ai/`) — runs a PydanticAI agent as one governed AgentOS step. Same config keys, same output keys and the same effects as `agentos-provider-openai-agents`; a test runs one scripted trajectory through both executors and asserts parity, so a workflow switches harness by changing `executor`. One `Agent.run` per step on its own `asyncio.run` loop, client closed in `finally`; `max_turns` → `UsageLimits(request_limit)`; a tool needing approval or external execution comes back as `DeferredToolRequests` and the executor **raises** naming the tools; `ModelHTTPError` mapped by status; the client is built from `AGENTOS_PYDANTIC_AI_*` only (`OPENAI_BASE_URL` ignored, tested); SDK instrumentation never enabled. Core forbids importing `pydantic_ai`.
- **Shared tool registry** — `ToolSpec` / `ToolRegistry` / built-ins moved to `agentos.providerkit.tools` under the SDK-neutral entry-point group **`agentos.tools`**. One registration serves both harnesses. `openai-agents` still loads its original `agentos.openai_agents_tools` group for this release. `strip_fences` moved to `agentos.providerkit.prompt`.
- **Rejected tool calls are visible in the log.** Live on `qwen2.5:0.5b`, the model invented an extra argument; PydanticAI rejected the call without running the tool and the trajectory showed `output_sha256: null` — indistinguishable from "no return". A rejected call is now recorded with `rejected: true` and the retry message hashed.
- **CI runs on `providers/**`** — the pull-request path filter omitted it, so a providers-only PR ran no CI.
