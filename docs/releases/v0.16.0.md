## v0.16.0 — Run controls, decisions in place, first hour, four-seat review

Six merged pull requests since `v0.15.0`, all on the operator UI and the tests around it, plus
one store fix. Each UI change came out of a comparison against the run pages and approval
screens of Temporal UI, Argo Workflows, Hatchet, Inngest, Prefect, Dagster, Windmill, Airflow,
n8n and agent-inbox — facts pulled live and their source read, with the rejected patterns
recorded alongside the adopted ones. No engine, API or event changes: golden logs are unchanged,
no routes or settings were added, `docs/FAIL_MODES.md` is identical to `v0.15.0`.

### Operator UI

- **Run controls on the run page** (#95) — Pause, Resume, and Cancel (two-step inline confirm
  with a reason). Enabled state mirrors the engine's 409 rules so a disabled button and a 409
  never disagree; the principal rule is the inbox's.
- **Node selection** (#95) — click a graph node or its cost row for a step detail strip; the
  timeline narrows to that step's and run-level events; *Retry step* is offered only when the
  fold says failed or dead-lettered, and never against a time-travelled fold.
- **Expandable event rows and a filtered runs list** (#95) — the full record as stored; status
  chips with counts and an id-prefix / workflow filter held in the URL, captioned as client-side
  over the loaded page.
- **One `ApprovalCard` for the inbox and the run page** (#96) — links to its run, says
  *Recorded as `<id>`* next to the actions, states each verb's consequence from the engine's
  semantics, and warns without disabling when a non-human principal faces a human-only class. A
  *what this approves* disclosure shows the step's agent, the run's inputs, upstream outputs,
  cost so far, attempts and the budget rule, fetched once on open. The run page gains an
  Approvals panel: pending gates are decided in place, decided gates show who, why and when.
- **First hour** (#97) — empty inbox and runs states say how to cause a gate and link
  `docs/tutorial.md`: a diamond run with no model, from define to time travel, executed by
  `tests/test_tutorial.py` against the real API with every printed number pinned.
- **Integrity verdict, deny wording, opt-in notification** (#98) — a verdict chip on the run
  header from `GET /runs/{id}/integrity` (verified / unsigned / unverifiable / INVALID / chain
  broken); the non-human warning states the outcome the engine will reach from the workflow
  definition and `GET /policy`; a top-bar switch enables a browser notification for gates that
  arrive after the page loaded, carrying nothing decidable.
- **Polish** (#94) — one status vocabulary across graph, legend and cost table; copy-button run
  id; failure and loading cards; in-flight Approve/Reject labels; favicon; sticky table heads
  that actually stick.

### Store

- **SQLite reads serialised** (#94) — the adapter shares one connection across the API's
  thread pool; twelve read paths bypassed the writer lock, and two overlapping statements
  raised `SQLITE_MISUSE` (a 500 on the run page's first paint). All reads go through locked
  helpers; locked by an 8-thread burst test on every adapter.
- **`migrate()` under the lock** (#99) — it ran on the raw connection, and the lock was created
  after it; a re-run overlapping a read received the read's rows. Lock first, held end to end.

### Four-seat review (#99)

Staff / Product / Security / CTO pass over #94–#98 with the code-reviewer skill and
`cqa-analyzer` before/after: five items accepted and fixed red-first (a UI↔engine drift lock
via one shared truth table; the tutorial's numbers pinned; the store lock above; a redundant
header chip; `importorskip` in two provider test files), ten declined with the evidence that
cleared them, one deferred. Record: `docs/reviews/2026-09-22-four-seat-review-v0.16.0.md`.
