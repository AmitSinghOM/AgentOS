## v0.17.0 — Triggers, Slack notifier, ACP provider, hardening, first PyPI release

Twenty-two merged pull requests since `v0.16.0`, in three groups: three features that let a run
start, be heard about and be executed with nobody at a terminal (#105 ACP provider, #106
triggers, #107 Slack notifier, reviewed together in
[`docs/reviews/2026-09-28-self-review-acp-triggers-slack.md`](../reviews/2026-09-28-self-review-acp-triggers-slack.md));
hardening of what the repository hands an operator to copy (#108/#109 compose, #111 UI assets,
#128 Dockerfile and asserted mode); and the docs, dependency, CI and audit work that made this
tag possible (#101, #110, #102–#104, #113–#116, #118, #119, #123–#125, #126). Golden logs are
unchanged and no event type was added. One
route (`POST /triggers/webhooks/{name}`), one optional body field (`RunStartBody.principal`),
seven environment variables and 15 `docs/FAIL_MODES.md` rows were added. This is the **first
release that uploads to PyPI**: `dagentos` and the five `agentos-provider-*` distributions
publish from the tag's `publish.yml` run through Trusted Publishing (`docs/RELEASING.md`), so
the documented install line and the providers install from PyPI from this release on.

A repository audit on 2026-11-12 (kept outside the repository) ordered the last four PRs below
and the release itself; its rows are cited by id (I-01…) where a change answers one.

### Features

- **ACP provider** (#105) — `agentos-provider-acp` runs one
  [Agent Client Protocol](https://agentclientprotocol.com) turn as one governed step:
  `kiro-cli acp` by default, any ACP agent via `AGENTOS_ACP_COMMAND` (a JSON list), standard
  library only since ACP is newline-delimited JSON-RPC 2.0 over stdio. The governance seam is
  the agent's `session/request_permission`: it is answered from the step's declared effect
  classes (ACP `ToolKind` → `EffectClass`) — declared → `allow_once`, undeclared →
  `reject_once`, never `allow_always`. A tool the agent runs *without* asking is reported by
  class, so an unasked `edit` under `[compute, read]` is dead-lettered by the existing `_settle`
  as an undeclared effect; a rejected request never ran and is recorded as `permission:
  rejected`, not as an effect. Recorded per step: `text`, `stop_reason`, `tool_calls[]`
  (title / kind / status / effect class, SHA-256 of input and output, never inlined), `usage`,
  `cost` (`tool_calls`, `context_tokens_used`; the amount is what the agent reports — kiro-cli
  sends no `usage_update` today, so `0`). One process per step, no `fs`/`terminal` capability
  advertised, `session/cancel` + SIGTERM/SIGKILL on timeout or engine cancel, `progress()` on
  every frame renews the lease. Pinned by 43 tests that drive a real fake agent over real stdio
  (`providers/acp/tests/fake_acp_agent.py`), including unasked tool → dead-letter through the
  core, the permission answer asserted on the wire, hang-kill, crash and version mismatch; the
  self-review added `test_a_tool_that_ran_and_failed_is_still_an_effect` after finding that a
  *failed* tool call had been excluded from `ran_classes`. No FAIL_MODES rows: the provider adds
  no chokepoint of its own, the gate and `_settle` are the core's. `AGENTOS_ACP_CWD`,
  `AGENTOS_ACP_TIMEOUT` (600 s) complete the config; `ConfigError` names the variable.
- **Triggers** (#106; Phase 8 #5) — two ways to start a run with nobody at a terminal, both
  through `POST /workflows/{name}/runs` and its `Idempotency-Key`: no second door into the
  engine, same auth, same policy ceiling, same log. *Cron*: `python -m dagentos.triggers` is an
  HTTP client of the API — a five-field stdlib parser (steps, ranges, lists, Vixie day-of-month
  OR day-of-week, IANA `tz`; a never-firing schedule is a load error), key
  `cron:{name}:{slot ISO with offset}`, bounded backoff (1…60 s) inside the slot for at most
  10 minutes and never past the next slot, then one ERROR and give up; **missed slots are never
  backfilled**; `--dry-run` prints the next fire times. *Webhook*:
  `POST /triggers/webhooks/{name}`, mounted only when `AGENTOS_TRIGGERS` is set, authenticates
  the *delivery*: `X-AgentOS-Timestamp` + `X-AgentOS-Signature: v1=<hmac>` over
  `{timestamp}.{len(delivery)}.{delivery}.{body}`, ±300 s, constant-time compare; the optional
  `X-AgentOS-Delivery` is the idempotency key (else the body hash) and sits *inside* the signed
  string — the self-review's R1 found it outside, so one captured request replayed with fresh
  ids inside the window started a run per replay; the length prefix exists because the first
  cut `{ts}.{delivery}.{body}` collided on `"a.b"+"x" == "a"+"b.x"`. The secret is an env var
  the file *names*; a value in the file is a load error and an unset variable stops the API at
  startup. Checks before the engine, in order: 404 → 413 → 415 → 401 with
  `WWW-Authenticate: AgentOS-Webhook`. The route is the only entry in
  `auth.SELF_AUTHENTICATED_PREFIXES` (deliberately not `OPEN_PATHS`); `run.started` records
  `system` / `webhook:{name}` with attestation `hmac-sha256:v1`, and the body reaches prompts as
  delimited data under `run.trigger.body`. `RunStartBody.principal` is new and optional, resolved
  by `principal_for` like every other route (bearer mode still 422s it), so the cron runner can
  record `system` / `cron:{name}` in asserted mode. Ten FAIL_MODES rows (Webhook trigger ×5
  incl. replay under a new id, Triggers startup, Cron runner ×4), each pinned in
  `tests/test_triggers.py` (62 tests at merge). `docs/triggers.md`, `examples/triggers.json`.
- **Slack approval notifier** (#107; Phase 8 #6) — `dagentos/notify/slack.py`, an `Observer`
  composed in `build_observers` with the store resolver so it works in the worker (which appends
  the request) and the API (which appends decisions). Posts to a Slack incoming webhook on
  `approval.requested` (effect and cost kinds) and on `approval.granted` / `rejected`, naming
  the principal's kind and id and the reason, with a deep link to `/ui/runs/{id}` built from
  `AGENTOS_UI_URL`. It **carries no authority**: no approve button, no token, no decision URL —
  an incoming webhook can verify nobody, so the decision stays in the UI/API where the bearer
  principal is. It is **not on the engine's path**: `observe()` enqueues and returns, one lazily
  started daemon thread posts with a 5 s timeout, a bounded queue (100) drops the *oldest* with
  a WARNING, `close()` drains on clean stop (and at exit in the API). Slack down / slow / non-2xx
  is a WARNING naming the approval and never the URL, which is a credential. Every field comes
  from the event and the resolved fold, so a replayed log posts identical text; the principal's
  `attestation` stays out of chat. `AGENTOS_SLACK_WEBHOOK` must be
  `https://hooks.slack.com/services/…` (exact host) or the process refuses to start naming the
  variable, never echoing the path. Four FAIL_MODES rows pinned in `tests/test_slack_notifier.py`
  (23 tests). `docs/notifications.md`.

### Hardening

- **Compose on loopback, no literal credential, Grafana Viewer** (#108, #109) — every `ports:`
  entry in `docker-compose.yml` now carries `127.0.0.1:`; a bare `HOST:CONTAINER` binds
  `0.0.0.0`, so `docker compose up` on a laptop had published Postgres 5432 (fixed password),
  Jaeger 16686 and the OTLP intake 4318, Prometheus 9090 and an anonymous-**Admin** Grafana 3000
  to whatever network the machine was on. `POSTGRES_PASSWORD` is
  `${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD in .env (cp .env.example .env)}` — compose refuses
  to start without it; `.env.example` sets the development value uncommented so the README quick
  start and the CI `compose` job work unchanged. Grafana's anonymous role is Viewer (dashboard
  and datasource are provisioned read-only from files). Six locks in
  `tests/test_c13_mit_and_compose.py`, each red on the prior file, with a count guard so a regex
  that matches nothing cannot pass vacuously.
- **Precompressed UI assets** (#111) — `ui/scripts/precompress.mjs` writes brotli and gzip
  siblings for every text asset at build time (Node's own zlib, no dependency); the `/ui/assets`
  mount serves them on `Accept-Encoding` with `Content-Encoding`, `Vary`, the original media type
  and per-variant 304s. Nothing compresses per request, so the JSON API and the SSE stream are
  untouched. A direct request for `app.js.br` is typed `application/octet-stream` (Python's
  `mimetypes` would say `text/javascript`), so a browser never executes compressed bytes.
  `bundle_ui.py` refuses a build whose siblings are missing, bloated or fail a gzip round-trip.
  Nine tests in `tests/test_ui_mount.py`.
- **Asserted-mode tool deny, Dockerfile on loopback** (#128; audit I-05) — the image defaults to
  `AGENTOS_AUTH=asserted`, binds `0.0.0.0` in-container, and the Dockerfile's own header example
  published `-p 8000:8000` on every interface. In asserted mode any caller could `POST /agents`
  a `tool` agent and run it with `?sync=true` in the API process: `kind: subprocess` runs
  arbitrary argv as the image's user, and a `${NAME}` header sends the API's own environment to
  any URL. Now `POST /agents` in asserted mode refuses (403, before the store, naming the shape
  and the opt-in) a `tool` agent that meets **any** of three conditions: (1) `config.kind` is
  `subprocess`; (2) a `${NAME}` reference appears in a value of `config.headers` or
  `config.env`; (3) `config.allow_private_networks` is true. The opt-in is the purpose-named
  `AGENTOS_ASSERTED_ALLOW_UNSAFE_TOOLS=1`, which logs a WARNING at startup; bearer mode ignores
  it (the token already names an operator). `examples/repo_facts_agent.json` (http, literal
  headers) uses none of the three, so the quickstart keeps working. The Dockerfile example now
  reads `-p 127.0.0.1:8000:8000`; no `ENV AGENTOS_AUTH=bearer` was added to the image, because
  bearer without a token file refuses to start and the README's loopback path would break. One
  FAIL_MODES row, pinned by
  `tests/test_auth.py::test_asserted_mode_refuses_unsafe_tool_agents_unless_opted_in` (four
  shapes, 403 then 201 with the opt-in) and
  `test_safe_tool_agents_and_bearer_mode_register_as_before`. Also in `SECURITY.md` and
  `.env.example`.
- **Webhook OpenAPI text** (#128; I-06) — the served description of `POST /triggers/webhooks/{name}`
  said the HMAC was over `{timestamp}.{delivery}.{body}` while the verifier signs the
  length-prefixed string above, so anyone who built a sender from `/docs` got 401 on every
  delivery. The description (and the `verify` docstring) now name
  `{timestamp}.{len(delivery)}.{delivery}.{body}` and state that `delivery` is empty and `len`
  is `0` when the header is absent; `test_openapi_description_states_the_length_prefixed_signed_string`
  asserts the served text contains the right string and not the wrong one.
- **Egress guard refuses 100.64.0.0/10** (#128; I-07) — RFC 6598 shared address space is neither
  private nor global to Python (`is_private` is False) and some clouds serve their metadata
  service from it (100.100.100.200). `_check_egress` now refuses it by name, IPv4-mapped IPv6
  included, with no opt-in — `allow_private_networks` does not open it, as the extended test in
  `tests/test_tool_agent.py` pins.

### CI red since 2026-10-26, and why (#126; I-01, I-02)

Both `test (3.11)` / `test (3.14)` and `audit` were red on every PR for three weeks; neither
failure was caused by the PRs that showed it, and `main` has no scheduled run, so the drift was
visible only as red checks on Dependabot PRs.

- **pydantic-ai: a refused tool call logged as a normal return.** pydantic-ai 2.60.0
  (2026-10-23) deprecated `RetryPromptPart`; an argument-validation failure is now answered by the
  call's own `ToolReturnPart(outcome="retried", retry=RetryInfo(cause="validation_error"))`.
  `_trajectory` in the provider executor only recognised `RetryPromptPart`, so since 2.60 the
  refused call landed in the run log as a normal tool return with the validation-error list
  hashed as its "output" — the exact ambiguity the provider README says the log prevents. The
  floor `pydantic-ai-slim[openai]>=2.46,<3` admitted every new version, and CI resolves the
  latest. Fix: a `ToolReturnPart` whose `outcome == "retried"` is recorded as `rejected: true`
  with `sha256(model_response_str())`; the `RetryPromptPart` branch stays for 2.46–2.59. The
  floor was kept on purpose (the old part is only deprecated until V3 and a serialized history
  can still carry it). Two tests build each part shape by hand so they do not depend on which
  pydantic-ai is installed; with only `executor.py` stashed, `pytest -k rejected` fails 2 of 3.
- **`npm audit --audit-level=high` red on undici 8.11.2** via `jsdom` 30.1.2, a devDependency —
  nothing in `ui/dist` ships it, but no PR could merge green. Only the `node_modules/undici`
  block of `ui/package-lock.json` moved (8.11.2 → 8.12.4); `package.json` untouched.

### Operator-facing changes

| Variable | Added by | What |
| --- | --- | --- |
| `AGENTOS_TRIGGERS` | #106 | triggers file; webhook routes mounted by the API, cron fired by `python -m dagentos.triggers`; bad file or unset `secret_env` stops startup naming the trigger and field |
| `AGENTOS_SLACK_WEBHOOK` | #107 | Slack incoming webhook (`https://hooks.slack.com/services/…` only); unset → nothing |
| `AGENTOS_UI_URL` | #107 | base of the run link in Slack notices (default `http://127.0.0.1:8000/ui`) |
| `AGENTOS_ACP_COMMAND` / `AGENTOS_ACP_CWD` / `AGENTOS_ACP_TIMEOUT` | #105 | the ACP agent program as a JSON list (default `["kiro-cli","acp"]`), the absolute path a session runs in, seconds per turn (600) |
| `AGENTOS_ASSERTED_ALLOW_UNSAFE_TOOLS` | #128 | `1` lets unverified callers register subprocess / `${NAME}` / private-network tool agents in asserted mode; off by default |
| `POSTGRES_PASSWORD` (compose) | #109 | required by `docker-compose.yml` via `${…:?}`; set in `.env.example` |

The Dockerfile's example and `docs/RELEASING.md` publish the API on `127.0.0.1:8000:8000`;
`docker-compose.yml` publishes every port on loopback; Grafana is anonymous Viewer.

### Install

```bash
pip install "dagentos[providerkit]" agentos-provider-openai-compat
uvicorn dagentos.api.main:app && open http://localhost:8000/ui/
docker run --rm -p 127.0.0.1:8000:8000 ghcr.io/amitsinghom/agentos:0.17.0
```

First PyPI release: the line above and `pip install agentos-provider-{anthropic,openai-agents,pydantic-ai,acp}`
resolve from PyPI once the tag's publish run completes. Every wheel and the image carry
Sigstore-signed provenance; `docs/RELEASING.md` shows how to verify.

### Events and API

No new event types; golden logs unchanged. New route `POST /triggers/webhooks/{name}`
(self-authenticated by HMAC, present only when `AGENTOS_TRIGGERS` is set). `RunStartBody`
gains an optional `principal` (asserted mode; 422 in bearer mode like every other body
principal). `run.started` may now carry a `system` principal (`webhook:{name}`,
`cron:{name}`). No port methods or migrations added.
