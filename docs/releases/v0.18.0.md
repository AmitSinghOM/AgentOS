## v0.18.0 — Hardening, operability, run index, archive, function calling

Seventy-five commits and twenty-one merged pull requests since `v0.17.1`, all of them ordered by
the repository audit of 2026-11-12 (kept outside the repository; rows are cited by id, `I-…` for
issues and `E-…` for enhancements) and landed in three waves. **Wave 1** (#134–#138) closed the
audit's blocker rows: scheduled CI so a dependency drift shows up on `main` the day it happens,
tool output read under a byte cap instead of into memory, substituted secrets scrubbed from what
the log records, a stream reconnect that no longer mislabels a live run, and a deployment-wide
kill switch. **Wave 2** (#139–#146, #150) paid down tooling and supply-chain debt: a real ruff rule
set and a mypy baseline gate, every CI action pinned by commit SHA, an image that installs from
hash-pinned constraints, a documentation drift sweep with four reconstructed ADRs, community files,
and `agentos init` / `agentos run`. **Wave 3** (#148, #149, #151–#154) added the operability the
audit ranked highest: a rebuildable `runs` index behind a server-side `GET /runs?status=`, a run
export an auditor can take away, a retention command that purges only what it has already exported
and verified, a function-calling round trip for the plain OpenAI-compatible provider gated by the
step's declared effect classes, six Hypothesis properties over random logs, and four more Toxiproxy
scenarios. Two migrations (3 and 4), one read-only route (`GET /scheduler`), three query parameters
on `GET /runs`, six CLI subcommands and 11 `docs/FAIL_MODES.md` rows were added. No event type was
added and the golden logs are unchanged. Every row the audit called a blocker is closed; what stays
open is listed at the end and in `ROADMAP.md` "Open items".

### Wave 1 — hardening (audit blockers)

- **Scheduled CI on `main`, nightly for all five providers** (#134; I-11) — `ci.yml` gains
  `schedule: cron "37 4 * * *"`, and its `concurrency.group` now includes `github.event_name` so
  a scheduled run and a push to `main` cannot cancel each other (both resolved to
  `refs/heads/main` before). Every job runs on the schedule, including the fresh 3.11 + 3.14
  resolve, so a floor drift like the pydantic-ai 2.60 break that stayed invisible for three weeks
  before `v0.17.0` now fails on `main` within a day. `provider-live.yml` gets
  `permissions: contents: read`, installs the same five providers as the `test` job (acp was
  missing) and replays all five suites (`pytest -q providers tests/test_quickstart_llm.py`).
  Pinned by `tests/test_packaging.py::test_main_is_checked_daily_and_the_nightly_replays_every_provider`.
- **Five small hardening rows** (#136; I-10, I-15, I-18, I-16/I-37, I-42) — (1) a worker thread
  that dies mid-test now fails the test: `pyproject.toml` sets
  `filterwarnings = ["error::pytest.PytestUnhandledThreadExceptionWarning"]`, which exposed one
  test appending an unchained cancel "as the API would" (the real API chains through
  `engine._emit`; the test now calls `request_cancel`). (2) `agentos.db` is created `0600`:
  `SqliteStore` opens a not-yet-existing plain path with `os.open(O_CREAT | O_RDWR, 0o600)` before
  `sqlite3.connect`, and SQLite copies that mode onto the `-wal`/`-shm` sidecars
  (`tests/test_store_typed_and_bounded.py::test_sqlite_file_is_created_owner_only`). (3)
  `AGENTOS_PG_SCHEMA` must match `^[a-z_][a-z0-9_]{0,62}$` or `store_from_env` refuses before any
  connection, naming the variable and the rule (it is interpolated into `CREATE SCHEMA` and
  `search_path`). (4) `SECURITY.md` and `docs/TRUST_BOUNDARY.md` state that `/metrics` is open and
  what its labels carry, and both now list the real open paths (`/health`, `/ready`, `/metrics`,
  `GET`/`HEAD` of `/ui` static files, the self-authenticated `/triggers/webhooks/*`). (5) the
  image installs the acp provider wheel (`Dockerfile` had four of five);
  `tests/test_packaging.py::test_dockerfile_installs_every_provider_wheel` derives the set from
  `providers/*/pyproject.toml`.
- **Tool executor: streaming byte caps and redaction** (#137; I-08, I-14) — `max_bytes` (default
  1 MiB) was checked after the whole body was in memory. Now the http path uses `c.stream()` +
  `iter_bytes()` with a running counter (after decompression, so a compressed body cannot slip
  under the cap) and abandons the body at the cap; the subprocess path replaces `communicate()`
  with a `selectors` pump that writes stdin as the pipe drains, reads stdout in 64 KiB chunks,
  keeps stderr as a 64 KiB tail (it was unbounded too) and `killpg`s the group past the cap. A
  hostile endpoint or program can no longer push gigabytes into the worker, or into the API
  process under `?sync=true`. Redaction: every value `_substitute` fills in for a `${NAME}`
  reference in this step's `headers`/`env` (values of 8+ characters) becomes `[REDACTED:NAME]`
  in the recorded body/JSON/headers, the stderr tail, the error text and `progress()` notes;
  `output.redactions` lists the *names* removed so replay stays deterministic and an auditor sees
  that something is missing. The outgoing request still carries the real value. A step that
  substitutes nothing records output verbatim with no `redactions` key, so existing runs replay
  unchanged. Known limits in the module docstring: values under 8 chars and secrets that come
  back transformed (encoded, JSON-escaped, split across the tail boundary); the general
  pre-append pass stays ROADMAP row 7. Five FAIL_MODES rows (one amended, four new), pinned in
  `tests/test_tool_agent.py` (`test_http_body_over_cap_is_refused_while_streaming_and_memory_stays_bounded`,
  `test_subprocess_endless_stdout_is_cut_at_the_cap_not_at_the_timeout`,
  `test_http_output_and_error_text_redact_the_substituted_header_value`,
  `test_subprocess_output_redacts_the_substituted_env_value`,
  `test_steps_without_env_references_record_output_unchanged`).
- **UI stream reconnect** (#135; I-09 / D6) — after the server closed the SSE stream at its
  maximum duration, `RunGraph.tsx` did one `refetch()`, and `refetch` returns `null` on *any*
  error, so one transient 5xx at that boundary set the chip to `closed` on a run that was still
  running. A `null` refetch is now a stream *error*: it counts toward `MAX_CONSECUTIVE_ERRORS`,
  backs off and retries; only a terminal status from the server closes the loop; a frame or a
  successful refetch resets the counter. Two vitest cases in `ui/src/RunGraph.test.tsx` (blip
  then recovery with `Last-Event-ID`; every refetch failing → "gave up after 5 attempts", chip
  `error`, never `closed`). UI tests 99 → 101.
- **Global pause** (#138; A12 / E-03) — the incident kill switch. `agentos pause --all
  [--reason ..] [--principal NAME]`, `agentos resume --all`, `agentos pause --status` write and
  read one deployment-wide fact: the newest row of a store-level, append-only `scheduler_state`
  history (**migration 3**, hash-pinned per dialect in `tests/test_migrations.py`; `SchedulerState`
  in `dagentos/core/events.py` says in its first line that it is *not* a run event, because the
  log is per run and replay must stay per-run deterministic). The engine consults it at every
  wave boundary after the per-run control check and before `_ready_nodes`, so the in-flight wave
  is recorded, nothing new starts, and the run stays `running` — the `?sync=true` path honours it
  too. The worker checks it before `queue.pull` and at the top of `recover()`: no pull, no
  re-enqueue, no approval expiry — the deployment is frozen, not drained. A run the engine
  stopped mid-advance is pushed straight back on the queue so the first tick after `resume`
  continues it. **Fail-closed:** a `get_scheduler_state()` that raises is treated as paused and
  logged with the exception class. `GET /scheduler` is read-only and bearer-gated; every write
  verb is 405, so a stolen API token cannot un-pause an incident (un-pausing takes store access).
  Trade-off accepted and documented: the pause history is auditable but not hash-chained or
  sealed. Three FAIL_MODES rows (84 → 87); `tests/test_global_pause.py` (9 tests), a store
  contract case for every adapter, migration 3 pinned.

### Wave 3 — operability

- **Run index** (#151; E-07) — the log is the truth; the new columns are a rebuildable index of
  it, and nothing that decides anything reads them. **Migration 4** adds to `runs`: `status`
  (the fold's `RunStatus`), `pending_approvals` (JSON; so an `approval.granted` can tell whether
  it was the last pending one), `indexed_seq` (the last seq the row reflects, so a row behind its
  log is detectable) and `updated_at`, with indexes `(status, created_at, run_id)` and
  `(created_at, run_id)`. One pure function, `dagentos/core/run_index.py::index_events`, mirrors
  `fold._apply`'s transitions and every adapter calls it *inside the transaction that appends
  the events* (SQLite `BEGIN IMMEDIATE`, Postgres under the run row's `FOR UPDATE`), so the row
  never disagrees with the fold at a commit boundary. **Backfill and catch-up live in
  `migrate()`:** after migrations apply, every run whose row is behind its log is re-indexed, one
  short transaction per run — on the upgrade that is every run. SQLite migrations became atomic
  (ledger read, scripts statement by statement, ledger rows in one `BEGIN IMMEDIATE`) because
  SQLite has no `ADD COLUMN IF NOT EXISTS`; a current database is only read on open and takes no
  write lock. Contract: `Store.list_runs(status=, workflow=, cursor=, limit=) -> RunPage` and
  `run_status_counts()`; `GET /runs?status=&workflow=&cursor=&limit=` (422 on a bad status, 400
  on a foreign cursor) returns `next_cursor` and store-wide `counts`; the cursor is
  `(created_at, run_id)` — not `updated_at`, which a status change bumps and would skip the run
  on later pages (mutation M6 showed it). A row whose index disagrees with its fold is left out
  of a status filter, never shown under the wrong status. `GET /approvals` and the worker sweep
  fold only the runs the index lists; `agentos doctor` gains a read-only `runs index` row
  ("N/N rows agree with the fold"). UI run list: server-side status chips with store-wide counts,
  workflow filter, **Load more** on the cursor. One FAIL_MODES row (87 → 88). Locks:
  `tests/test_run_index.py` (index == fold at every cut point of every golden and seeded log;
  backfill of a `v0.17.1`-shaped database; atomic migration re-run; nulling `indexed_seq`
  rebuilds), `tests/test_run_index_api.py`, five contract cases per adapter, four vitest cases;
  11 targeted mutations all caught.
- **`agentos export-run`** (#149; A11 / E-08, E-06) — `agentos export-run (--run ID | --all)
  --format jsonl [--out PATH|-] [--include-blobs]` writes one run (or every run, one stream,
  oldest first) as JSON Lines: a header
  (`{"kind":"agentos.export","version":1,"run_id","exported_at","chain":{verified,sealed_through,seals,error}}`),
  every event in seq order exactly as `GET /runs/{id}/events` returns it (hashes included, canonical
  lines: sorted keys, compact, ASCII — the same serialization `event_hash` hashes, so a reader
  re-verifies the chain with stdlib `json` + `hashlib`), one `{"kind":"blob",…}` line per
  referenced blob with `--include-blobs` (a missing blob is a marked line, not a gap), and a
  summary from `fold()`. **A failed chain exits 1 and the run is still exported**, header
  `verified: false`, summary `status: null`: the auditor needs the tampered record as stored.
  A re-export is byte-identical except `exported_at`; the `--out` file is `0600`. No new
  redaction (events are stored already redacted where #137 redacts). Logic in a new top-level
  `dagentos/export.py` over the core ports (`lint-imports` still 3 kept / 0 broken).
  `tests/test_export_run.py` (9), including a round trip that re-folds the file and equals the
  live API; ten behaviour mutations caught. E-06: `SECURITY.md` and `docs/TRUST_BOUNDARY.md` now
  say plainly that `execute_code` runs with the worker's privileges — a `tool` subprocess shares
  the worker's uid, filesystem and network and can reach the DSN; the ACP agent process inherits
  the worker's whole environment — and what an operator should do meanwhile.
- **`agentos archive`** (#153; E-08 second half) — retention without erasure. `agentos archive
  --older-than <N>m|h|d|w --out DIR [--status completed,failed,cancelled] [--include-blobs]
  [--dry-run | --yes]` (dry run is the default). Candidates come from the run index; **the index
  only picks, the fold decides**: each run is re-read, its chain and seals judged as `agentos
  verify` judges them, and folded — a run the fold does not call terminal is skipped as `index
  drift`. Export-then-purge, in that order: `write_run` to `DIR/<run_id>.jsonl.part` (`0600`),
  fsync, read back as an auditor would (every line parses, seqs 1..n, summary agrees), rename,
  fsync the directory; then — **only if `chain.verified`** — `Store.purge_run(run_id,
  expected_seq=n, blobs=…)` removes events, snapshot, queue and lease rows and the run row in one
  transaction, refused with `ConflictError` if the log's last seq moved (a retry appended since).
  An unverified chain is exported, **kept**, and exits 1: the store never destroys the only
  evidence of a tampering. A blob is deleted only if no remaining run's stored record contains
  its sha256 (checked inside the purge transaction). `DIR/ARCHIVE.jsonl` is an append-only,
  fsynced manifest with one row per exported run (`file`, `sha256`, `bytes`, `events`,
  `status`, `chain_verified`, `purged`, `blobs_removed`). Afterwards the run is gone from
  `GET /runs`, `counts`, `verify --all` and `doctor`; the export file is the record and re-folds
  to the pre-purge `GET /runs/{id}`. `docs/REPLAY.md` states the boundary: this is retention, not
  erasure — the file holds every event; true erasure is A7 crypto-shredding, still open. Three
  FAIL_MODES rows (88 → 91); `tests/test_archive_runs.py` (19 collected) and three contract cases
  per adapter.
- **Function calling on `openai-compat`** (#148, #154; A8 / E-17) — the plain OpenAI-wire
  provider (Ollama, vLLM, LM Studio, OpenRouter, OpenAI) had no tool round trip; operator tools
  worked only through the two SDK harnesses. Agent `config` gains `tools` (registered names),
  `tool_choice` and `max_tool_rounds` (default 4). **Offer:** `ToolRegistry.select(config.tools,
  declared_effects)` — the rule both harnesses apply — sends only tools whose effect class the
  step declared, as OpenAI `tools` with a JSON Schema from the function's annotated signature.
  **Check before anything runs:** a call to a tool that was not offered (undeclared class or
  unregistered name) or whose arguments fail validation is **rejected**: the function never runs,
  the record says `rejected: true`, the refusal goes back as that call's `role: tool` result so
  the model can still answer or retry. **Return as data:** an executed tool's result goes back

  `DATA_BOUNDARY` (C12). **Bounded:** past `max_tool_rounds`, or on a tool that raises, the step

### Operator notes

- **Two migrations run on first start.** Migration 3 creates `scheduler_state` (instant).
  Migration 4 adds four columns and two indexes to `runs` and then **backfills the index for
  every existing run**, one short transaction per run, before the process serves — time grows
  with the number of runs in the store (each run is folded once). Both dialects are safe to
  re-run: SQLite applies each migration with its ledger row in one `BEGIN IMMEDIATE`
  transaction (a second process starting at the same time waits, then finds the ledger row);
  Postgres uses `ADD COLUMN IF NOT EXISTS`. On a large store, start one process first so the
  backfill runs once. Rebuild the index at any time: `UPDATE runs SET indexed_seq = NULL`, then
  restart.
- **New CLI surface:** `agentos pause --all | resume --all | pause --status`, `agentos init
  <dir>`, `agentos run <workflow.json>`, `agentos export-run`, `agentos archive`. All read the
  store from the environment like `verify` and `doctor`. `archive` is dry-run by default and
  needs `--yes` to purge; a cron job around it is the operator's.
- **New API surface:** `GET /scheduler` (read-only; 405 on every write verb; 503
  `{"paused": true, "store": "<ExceptionClass>"}` on a store fault, like `/ready`).
  `GET /runs?status=&workflow=&cursor=&limit=` with `next_cursor` and `counts` in the response
  and `updated_at` per item. `?limit` alone behaves as before.
- **Pause semantics:** while paused, nothing is pulled, re-enqueued or dispatched *and approval
  expiry does not tick*; in-flight steps finish and their wave is recorded; runs stay `running`.
  A store fault reads as paused. Un-pausing takes store access (the CLI), never the API.
- **Tool output** is now redacted where a `${NAME}` value comes back (`[REDACTED:NAME]`,
  `output.redactions`), and cut at `max_bytes` while streaming; stderr is kept as a 64 KiB tail.
  Steps that substitute nothing are byte-for-byte as before.
- **Unchanged from `v0.17.0`:** the asserted-mode tool deny (`POST /agents` refuses subprocess /
  `${NAME}` / private-network `tool` agents without `AGENTOS_ASSERTED_ALLOW_UNSAFE_TOOLS=1`),
  `127.0.0.1` binds in the Dockerfile example and compose, every environment variable. No new
  runtime environment variable in this release (`AGENTOS_PROPERTY_EXAMPLES` and
  `AGENTOS_LIVE_TOOLS` are test-only).
- **CI and image:** the `audit` job's blocking `npm audit` now covers production dependencies
  only (`--omit=dev`); the dev tree is audited as a warning (today: picomatch
  GHSA-fc5q-39xc-vjpf, no fix published). The image installs every third-party distribution from
  `deploy/constraints.txt` with `--require-hashes`; refresh it (`python
  scripts/refresh_constraints.py`) after Dependabot `pip` merges — `--check` says whether it is
  stale. A new `typecheck` job fails only on a mypy error not in `mypy-baseline.txt`. The
  nightly pulls `qwen2.5:1.5b` as well as `qwen2.5:0.5b` and fails closed if Ollama's installer
  changes.
- **Retention is not erasure.** `agentos archive` moves rows out of the store into a `0600` file
  that still holds every event (and every blob with `--include-blobs`); A7 crypto-shredding is
  still open.

### Install

```bash
pip install "dagentos[providerkit]" agentos-provider-openai-compat
uvicorn dagentos.api.main:app && open http://localhost:8000/ui/
docker run --rm -p 127.0.0.1:8000:8000 ghcr.io/amitsinghom/agentos:0.18.0
```

Or, without a server: `pip install dagentos && agentos init demo && cd demo && agentos run workflow.json --agents agent.json`.

All six distributions — `dagentos` and `agentos-provider-{openai-compat,anthropic,openai-agents,pydantic-ai,acp}`
— publish from this tag's run at `0.18.0`. Every wheel and the image carry Sigstore-signed
provenance; `docs/RELEASING.md` shows how to verify.

### Events and API

No new event types; golden logs unchanged (`tests/golden/`, and now
`tests/property/test_fold_determinism.py` over random logs). `SchedulerState` is a store record,
not an event. New route `GET /scheduler` (read-only). `GET /runs` gains `status`, `workflow` and
`cursor` query parameters (`limit` existed) and `next_cursor`, `counts`, per-item `updated_at` in the
response. Store port: `get_scheduler_state` / `set_scheduler_state` (#138), `list_runs` /
`run_status_counts` (#151), `purge_run` (#153). Migrations 3 and 4. `tool` executor output may
carry `redactions`. openai-compat `step.completed` output may carry `tool_calls`,
`tools_offered`, `tools_withheld`, `turns` when `config.tools` is set.
