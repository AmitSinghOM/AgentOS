## v0.11.0 — `dagentos`

A rename, and nothing else. The import package `agentos` collided with the PyPI project `agentos` (agentos.org), which is why v0.9.0 and v0.10.0 shipped as `agentos-durable` with the import package left as it was. `agenticos` was checked as a target and is also taken (PyPI, 21 releases, import package `agenticos`). `dagentos` — a *d* for durable — was free on PyPI, npm and GitHub on 2026-09-20, so from this release the distribution and the import package are one name.

### What changes

- **`pip install dagentos` → `import dagentos`** (#62). Every module moved from `agentos/` to `dagentos/`; the API target is `dagentos.api.main:app`, the worker is `python -m dagentos.worker`, the UI bundle lives at `dagentos/_ui`. Providers depend on `dagentos[providerkit]>=0.11`. Import-linter root and contracts follow the package.
- **Breaking** for anyone who imported `agentos.*` from this project — hence the minor bump. `import agentos` now fails (tested).

### What does not change, on purpose

Product names that collide with nothing: the `AGENTOS_*` environment variables, the `agentos` CLI, the `agentos.executors` / `agentos.tools` entry-point groups, the `agentos.*` logger and OpenTelemetry attribute namespaces, the `agentos.db` default store file, the `agentos-provider-*` distributions, and `ghcr.io/amitsinghom/agentos`. Earlier release notes are unchanged history.

### Install

```bash
pip install "dagentos[providerkit]" agentos-provider-openai-compat
uvicorn dagentos.api.main:app && open http://localhost:8000/ui/
docker run --rm -p 8000:8000 ghcr.io/amitsinghom/agentos:0.11.0
```

### Events

No new event types, routes or parameters. Golden logs are unchanged and still fold.

### Numbers

509 Python tests; 34 UI tests. Two things a mechanical rewrite would have missed, caught before merge: `scripts/bundle_ui.py` assembled the destination from separate path components, so the first wheel rehearsal shipped the stale bundle from the old directory; and `tests/test_ports.py` filtered `sys.modules` by the `"agentos"` prefix, which after the rename matched nothing and would have passed vacuously forever. Verified with a full packaging rehearsal (10 strict-clean distributions, fresh-venv install, release smoke, bundled UI resolving from `site-packages`) and a live API, worker and `agentos doctor` on the renamed package.

### Not in this release

Nothing was ever uploaded to PyPI as `agentos-durable`, so there is nothing to retire there. PyPI upload for `dagentos` remains behind the `PYPI_PUBLISH` repository variable pending the Trusted Publisher setup.
