## v0.14.0 — Production pass 2: lifecycle, probes, stream cost, supply chain

One merged pull request (#71): a second four-seat production review — Staff, Product,
Security, CTO — aimed at the surfaces the v0.13.0 pass had not reached: what the processes
do when the platform stops them, what the container tells its orchestrator, what an idle
watcher costs, and what a reporter of a vulnerability is supposed to do. Comparators
(Temporal, Prefect, Hatchet, Inngest, DBOS) were read live. Every accepted finding landed
with a test that fails on `v0.13.0`; every dismissed candidate is recorded with its reason.

### Fixed

- **The worker handles SIGTERM and SIGINT.** It runs as PID 1 in the image, and until now
  `docker stop` or a rollout killed it mid-step, leaving the run's lease held until
  `lease_ttl` expired (30 s of stall per in-flight run per deploy). `install_stop_signal()`
  flips the loop's `stop` predicate; the delivery in flight finishes its `advance()`,
  releases its lease, acks, and the process exits 0. A second signal exits at once and the
  lease expires by TTL. Locked by a real-subprocess test: old code exits `-15`, new code
  exits 0. New FAIL_MODES row "Worker process, SIGTERM / SIGINT".
- **`GET /ready` is a store round-trip.** `/health` stays 200 as liveness; `/ready` calls
  the new `Store.ping(timeout)` on the port (memory no-op, SQLite `SELECT 1`, PostgreSQL
  `pool.connection(timeout=)` + `SELECT 1`) bounded at 2 s, inside the image's 3 s
  `HEALTHCHECK` window, and answers 503 naming the exception class only — the message, which
  may carry a DSN, goes to the log. The self-review caught the first cut using
  `read_events`, whose PostgreSQL path waits on psycopg_pool's 30 s default and would have
  answered outside the probe window. `ping` has a contract test on all four adapters
  including live PostgreSQL. New FAIL_MODES row "Readiness probe".
- **The SSE stream holds no thread while idle.** `stream_run` was a sync generator under
  Starlette's threadpool, so every open tab held one of anyio's 40 tokens for its whole
  connection — FIFO, so N idle watchers meant proportional latency loss for every other sync
  route. It is now an async generator; store reads go to the threadpool only while actually
  reading. Test samples the limiter mid-poll: old code 1 token borrowed idle, new code 0.
  A client disconnect (`CancelledError`) ends the generator without a store-error log line.
- **Disclosure policy, dependency automation, audit gate.** `SECURITY.md`,
  `.github/dependabot.yml` (every distribution, the UI, the actions), and a CI `audit` job
  (`pip-audit --strict` over the resolved environment, `npm audit --audit-level=high`), all
  pinned by `tests/test_repo_hygiene.py`. Running the audits before trusting the job: `vite`
  6.4.3 clears a HIGH on the UI's build-time dev server (not in the shipped bundle); two held
  npm majors are a dated ledger in the ROADMAP. The job's own first run on the runner then
  failed — `--strict --skip-editable` is a contradiction, since a skipped editable
  distribution *is* a strict failure — and was fixed to freeze the resolved environment minus
  the editable projects and audit that file with `--no-deps`.

### Events and API

No new event types; golden logs unchanged. New route `GET /ready` (in `auth.OPEN_PATHS`,
no token required). New port method `Store.ping(timeout)`. The `Dockerfile` `HEALTHCHECK`
now probes `/ready`. No settings added or changed.

### Numbers

545 Python tests collected (`tests` + providers, chaos included; was 527); UI tests 54;
FAIL_MODES 68 → 70 rows. cqa: DSA 7.72 → 7.72, Design 9.41 → 9.44, Maturity 9.68 → 9.68,
findings 84 → 84 (the one new fingerprint is the `/ready` probe's report-never-raise boundary,
by design).

### Declared bound, not fixed

The image resolves third-party wheels from PyPI at build time under the library's `>=`
floors, so two builds of one tag can differ and the attestation covers floating inputs. The
fix is a constraints file used by the image and CI only (a library must not pin), with a
refresh process — its own slice, recorded in the ROADMAP. `SECURITY.md` commits to a 7-day
acknowledgement and a 90-day fix or assessment; those are the maintainer's numbers to keep.
