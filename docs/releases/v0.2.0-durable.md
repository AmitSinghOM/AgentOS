## Phase 1 — Durable Execution

A run survives the death of the process running it, and no step runs twice. The roadmap's demo is a test:

```
pytest tests/chaos/test_kill9_real_process.py -v
```

A real worker process is hard-killed (exit 137) right after step 2 of 3 commits; a second real process finishes the run through the SQLite file alone; step 2 is never even started again.

### What ships
- **Event-sourced run state.** Six event types, each with `event_type`, `schema_version`, `parent_run_id` and a dense monotonic `seq`. `fold(events)` is the single definition of run state; it refuses gaps and double completions. Upcaster registry for future schema versions. Golden replay corpus (`tests/golden/v0.2.0.json`) — a log written by this release must fold identically under every later release.
- **Resume is replay.** `Engine.advance()` re-derives everything from the log and skips completed steps. Runs are pinned to a workflow version and refuse to resume against a changed definition. Run start is idempotent on an `Idempotency-Key`.
- **Worker with fenced leases.** `python -m agentos.worker`. A strictly increasing fence per run; the store rejects any append with a stale fence, so a worker that stalls past its TTL cannot write even though it is still alive. Fence recorded at `acquire()`. Recovery sweep re-enqueues non-terminal runs on start.
- **Queue and lease are ports.** SQLite (stdlib), PostgreSQL (psycopg 3) and Memory adapters pass one contract suite (store + coordination). `pip install agentos` needs no infrastructure; Postgres is the production adapter; Redis is now an optional adapter, never a correctness dependency.
- **Chaos suite in CI.** `FaultInjector` with four named points; five in-process fault tests (both sides of the commit, lost ack, stalled-then-fenced worker, definition change) each asserting five steady-state invariants; the real-process kill test; and a Toxiproxy network test that injects 2 s of latency so a lease lapses mid-step and asserts the stale worker was rejected *by the fence*. CI jobs: `test` (3.11, 3.14, with Postgres service), `compose`, `chaos`, `chaos-network`.
- **API.** `POST /workflows/{name}/runs` → 202 (worker advances) or `?sync=true` → 201; `GET /runs/{id}` folded view; `GET /runs/{id}/events?after=seq` the raw log, paged.
- **Longevity structure** (`docs/DEVELOPMENT_STRUCTURE.md`): core imports no adapter (import-linter, enforced in CI), governance vocabulary (`EffectClass`, `Principal`, `BlobRef`) pinned as part of the log contract.

### Numbers
15 → 104 tests. Two real defects caught by the contract suites during development (fence reset on release; fence recorded on first write instead of acquire), both fixed before the crash test passed.

### Carried forward to Phase 2 (deliberately, not silently)
Widening the `Executor` port to `StepRequest`/`StepResult` with declared effects, metered cost, provenance and a progress heartbeat; provider plugins; snapshots; three further chaos points; ADRs 0006–0009. Reasoning is recorded in `ROADMAP.md` under the Phase 1 carry-forward decision.

### Landscape cons closed
#1 effects-before-ack, #2 idempotent append, #3 replay by id + version, #6 no process-local live state.
