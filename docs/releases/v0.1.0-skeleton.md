## Phase 0 — Walking Skeleton

The whole pipe is connected end to end: FastAPI API, in-memory agent registry, DAG-validated workflow definitions, a synchronous topological run of an echo agent, and `docker compose` bringing up Postgres + Redis with passing healthchecks.

### What ships
- `POST /agents`, `GET /agents` — agent registry
- `POST /workflows` — DAG definition with cycle rejection (400)
- `POST /workflows/{name}/runs` — synchronous run, returns the finished run
- `GET /runs/{id}` — fetch a run; 404 on unknown
- `GET /health`
- `docker compose up` — Postgres 16 + Redis 7 with healthchecks (unused by the API until Phase 1)
- 6 tests including the README quick start driven by the literal `examples/*.json` files
- CI on push, tags and PRs: ruff + pytest, plus a `compose` job that waits for both containers to be Healthy and asserts `pg_isready` / `redis-cli ping`

### What I'd do differently
The README `curl -d @file` lines shipped without a `Content-Type` header and returned 422. The quick start is now a test so it cannot drift again.
