## Phase 6 — Tools, snapshots, survey close-out

Every `landscape-con` issue from the survey that scoped this project is closed with an acceptance test cited. Replay is bounded, and the bound is verified.

### What ships
- **`tool` agent in core** (#38, `agentos/agents/tool.py`): HTTP and subprocess steps governed by the *existing* gate with no new mechanism — a GET reports `read`, anything else `write_external`, a subprocess `execute_code`, so a POST tool is suspended for approval before the request is sent. Host, path and argv are operator-fixed; inputs fill only query/JSON values (encoded) or arrive on stdin as JSON. `${ENV}` secrets are resolved from the worker's environment and redacted from output. 1 MiB response cap, egress guard (link-local never; private networks opt-in), process-group kill on timeout. Results flow through `wrap_input` (C12).
- **C13** (#13) is a test: MIT in `LICENSE` and all three `pyproject`s, no sign-up/paid-plan phrasing in user-facing pages, compose runs only open-source images.
- **C14** (#14): `docs/REPLAY.md` — state replay, not code replay — with the issue's acceptance test (a step rolls a random number, the process crashes, a fresh engine resumes from the store, the recorded roll survives; also a resume under a different executor implementation).
- **C10** (#10): every event type round-trips through every store adapter with equality; bounded reads.
- **C15 snapshots** (#15, #39): the engine reads a `WorkflowRun` snapshot and folds only the events after it (`fold_from`), verifying the chain link across the boundary. After review: the snapshot's anchor event is checked against the log even when the tail is empty; `put_snapshot` is monotonic per run on all three adapters (a fenced-out stale worker cannot regress it); a failing snapshot write never fails a committed `advance()` nor masks its exception; `AGENTOS_SNAPSHOT_EVERY` (default 200, 0 disables, invalid value names the variable) on both composition roots. `fold_from == fold` at every cut point of every golden log. Snapshots are derived: deleting them is safe; `GET /runs/{id}/integrity` never reads them.
- **Versioned migrations** (`agentos/store/migrations.py`) for SQLite and Postgres, applied and logged once each. Every released migration's SQL is SHA-256-pinned per dialect — editing one fails with "add migration N+1". A pre-ledger v0.6 SQLite database adopts the ledger without losing rows.
- **Dependencies:** `sqlalchemy` and `redis` removed from `pyproject.toml`, redis service removed from compose/CI/README/.env.example (queue and lease have been SQL adapters since Phase 1); import-linter still forbids both in the core.
- **Review:** PR #39 went through a four-seat debate (Staff / Product / Security / CTO), the code-reviewer skill (18/18 files, 12 anchored findings, security pass, reflection), and cqa-analyzer (Design 8.96 → 8.98). 10 findings: 9 fixed each with a locking test, 1 cosmetic declined with reason. Every dismissed item is recorded in the PR body.
